# Swin-T training/inference contract (Colab ↔ local)

A trained checkpoint (`models/swin_best.pt`) and a matching ONNX export are
connected. The local loader reads the checkpoint metadata, so future retraining
must keep saving the keys below. If metadata is missing, the loader falls back
to local defaults — for the class order that default was historically wrong
(inverted), which is exactly why saving `class_mapping` matters.

Source of truth for the local values: `swin_classifier.py`.

## Must match

| Item | Local value | Notes |
|---|---|---|
| Architecture | `timm.create_model("swin_tiny_patch4_window7_224", pretrained=True, num_classes=2)` | Confirmed by checkpoint `model_name`. Inference rebuilds with `pretrained=False` and loads your weights |
| Input size | `224 x 224` | Confirmed by checkpoint `image_size` |
| Color | RGB | Local crop starts as BGR from OpenCV, then converts to RGB. Train on RGB images |
| Resize | `cv2.resize(..., (224, 224), interpolation=cv2.INTER_LINEAR)` | Use `cv2` in the training `Dataset` instead of PIL/torchvision to guarantee pixel-identical resizing |
| Scaling | `float32 / 255.0` | i.e. pixels end in `[0, 1]` before normalization |
| Normalization | mean `(0.485, 0.456, 0.406)`, std `(0.229, 0.224, 0.225)` | Confirmed by checkpoint `image_mean` / `image_std` |
| Channel layout | CHW, batch dimension added at inference | |
| Classes | 2: `open`, `closed` | |
| Class index mapping | Checkpoint: `{"OPEN": 0, "CLOSED": 1}` | The loader adopts `class_mapping` (preferred) or `class_names`. Local fallback `{0: "closed", 1: "open"}` is only used when the checkpoint carries no mapping |
| Checkpoint path | `models/swin_best.pt` | Overridable with `--checkpoint` |
| Checkpoint format | `model_state_dict` inside a metadata dict | A bare `state_dict` is accepted but not recommended |
| ONNX (optional) | `models/swin_best.onnx` + `.onnx.data` | Generated by `export_swin_onnx.py`; loader prefers it when present |

## Checkpoint metadata to save

```python
torch.save(
    {
        "model_state_dict": model.state_dict(),
        "model_name": "swin_tiny_patch4_window7_224",
        "image_size": 224,
        "class_mapping": {"OPEN": 0, "CLOSED": 1},  # name -> training label index
        "image_mean": (0.485, 0.456, 0.406),
        "image_std": (0.229, 0.224, 0.225),
        "dataset": "MRL Eye",
        "val_accuracy": val_accuracy,
    },
    "/content/drive/MyDrive/drowsy_project/swin_best.pt",
)
```

`class_names` in label order (for example `("open", "closed")`) is also
accepted, but `class_mapping` is less error-prone because it states each index
explicitly. Do not save the classes in one order and the final layer in the
other.

## Dataset and split

- Dataset: MRL Eye (open/closed eye crops). CEW is optional.
- **Split by subject/person**, never randomly. MRL filenames encode the subject
  (`s1_...`, `s2_...`); hold out whole subjects for validation/test.
- Report subject-wise accuracy/F1, not only pooled numbers.
- MRL Eye images are **grayscale/near-infrared**, while the live webcam is RGB.
  That domain gap is real: after retraining, validate on recorded webcam clips
  as well as the MRL test split.
- MRL/CEW are **static eye-state** datasets; they cannot teach blink dynamics or
  dozing. For temporal drowsiness, use video datasets with event/level labels
  such as UTA-RLDD (alert / low vigilance / drowsy) or NTHU-DDD
  (sleepy/yawning/nodding driving clips). Check each dataset's research license.
- The local slow-blink tracker (`SLOW_BLINK_*` in `drowsy_pipeline.py`) is
  temporal logic on top of the open/closed output; it is not trained. Retraining
  on temporal data improves the underlying eye-state signal, while calibration
  only tunes thresholds.

## Eye crop the model will see at inference

Training images and live crops must match geometrically, otherwise accuracy
drops even when the checkpoint loads cleanly:

1. MediaPipe face landmarks (478 points).
2. Bounding box of the same six eye points used by EAR
   (left `362, 385, 387, 263, 373, 380`; right `33, 160, 158, 133, 153, 144`).
3. Expand the box by **10% padding**.
4. Make the crop **square**, centred on the eye. If the square would leave the
   frame, shift it back inside instead of squashing it.
5. Crop from the original webcam frame (no extra rotation).
6. Resize the square crop to 224x224.

The old 35%-padding wide crop was resized to 224x224 and squashed the eye; that
was one of the two live-accuracy bugs fixed on 2026-11-18. The other was the
inverted class order. If you retrain, generate training crops with this same
square pipeline (or augment MRL crops with square padding/scale/rotation) so the
model sees the same geometry.

## After training

1. Download `swin_best.pt` into `models/` (do not commit it; `*.pt` is ignored).
2. `uv sync --extra ml`
3. `python test_swin_setup.py` — all checks, including real inference, must pass.
4. `python swin_classifier.py` — confirm class order, normalization, backend.
5. `python export_swin_onnx.py` — writes `models/swin_best.onnx`, verifies logits
   against PyTorch, and prints CPU latency.
6. `python drowsy_pipeline.py --mode SWIN` — verify live alarm behavior.
7. Calibrate `--swin-threshold` on webcam clips (open/closed score distributions),
   then update `SWIN_CLOSED_THRESHOLD` if needed.
